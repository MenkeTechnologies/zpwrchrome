what it is

A drop-in replacement for the Go binary that the browserpass browser extension talks to via Chrome / Firefox native messaging — plus additive actions that browserpass-extension doesn't call but are wired into zpwrchrome: TOTP retrieval, whole-store fuzzy + substring search, browser-side GPG unlock, a multi-segment HTTP/HTTPS download manager, post-download command execution, filesystem crawl / program exec, and a CSL-JSON handoff to the zcite reference manager.

Single static binaryPure-Rust dep tree: serde, serde_json, ureq with rustls. No aria2, no system OpenSSL, no Go toolchain at runtime.
Wire-compatible with upstreamEvery action documented in browserpass-native's PROTOCOL.md v3.1.2 is implemented. Error codes 10–32 pin to the same integers; exit code = error code; version reported as 3.1.2 (packed int 3_001_002).
Strict 1:1 port disciplineEvery src/ported/ file mirrors a single upstream Go file. Every Rust fn carries /// Port of <name>() from <go_file>:<line>. Every Go comment carries over with // go:NN citation. Identifiers preserved verbatim (DetectGpgBinary, MakeConfigureResponse).
OTP extShells pass otp <entry> with PASSWORD_STORE_DIR set to the matching store. Returns the current TOTP code.
Search extHost-side fuzzy + substring scoring across every configured store. Faster than client-side fzf for large stores.
Unlock without a terminal extDecrypts a probe entry with a loopback pinentry to prime gpg-agent, so the GPG passphrase can be typed in the browser. --batch gpg can't prompt and a browser-spawned host has no TTY — this is what closes that gap.
Segmented downloads extN-segment Range GETs with retry / resume. Chrome cookies + User-Agent forwarded. File-state JSON tracker under $XDG_CACHE_HOME/zpwrchrome/dl/, so the queue survives a service-worker restart.
Post-download exec extrun.spawn executes a user-configured argv through std::process::Command — no shell anywhere on the path, so a filename can't introduce a quoting surface. stdout/stderr capped, 30 s default timeout (5 min max).
Host tools exthost.crawl / host.exec delegate to zwire_host::api — the same capability library the zwire agent runs, pulled in with default-features = false so its heavy PTY / sysinfo deps stay out of this tree.
zcite connector extzcite.save drops a CSL-JSON reference into zcite's inbox. A plain file in a shared directory — this MIT host never links the proprietary zcite engine.
Audit-friendly identifiersGo's PascalCase / camelCase preserved. File-level #![allow(non_snake_case)] makes this an explicit, documented decision rather than a style accident.
Drift pinned by teststests/ported_errors.rs pins every error code to its PROTOCOL.md value. tests/ported_version.rs pins version triple + packed int. tests/ported_integration.rs exercises every action end-to-end against the compiled binary.

extension actions additive

These are additive — browserpass-extension never sends them, so wire compatibility with upstream is preserved. They live under src/extensions/.

actionbehaviorwire shape
otp Shells pass otp <entry> with PASSWORD_STORE_DIR set to the matching store. Returns the current TOTP code. {action:"otp", storeId, file, settings} → {code:"123456"}
search Host-side fuzzy + substring scoring across every configured store. Faster than client-side fzf for large stores. {action:"search", settings, echoResponse:"<query>"} → {matches:[{store, path}, …]}
pass.unlock Enter the GPG passphrase from the browser instead of a terminal. Decrypts one probe entry with --pinentry-mode loopback --passphrase-fd 0 (passphrase on stdin, never argv, never disk), which primes gpg-agent for its default-cache-ttl so every later --batch decrypt succeeds through the unmodified ported path. The probe plaintext is discarded. {action:"pass.unlock", storeId, passphrase, file?, settings} → {unlocked:true, probe:"<entry>"}; a wrong passphrase returns error 24 with params.message = "Bad passphrase"
pass.lock Flushes every cached passphrase from gpg-agent (gpg-connect-agent reloadagent /bye), so the next decrypt needs the passphrase again. {action:"pass.lock"} → {locked:true}
run.spawn Executes a post-download argv via std::process::Command — argv[0] resolved against PATH, argv[1..] passed as literal C strings, no shell invocation. stdout/stderr truncated to their caps; default 30 s timeout, 5 min max, a runaway is killed with code 124. {action:"run.spawn", argv:[…], cwd?, env?, timeoutMs?} → {code, stdout, stderr, durationMs, truncated}
host.crawl Recursive filesystem walk, delegated to zwire_host::api::walk. {action:"host.crawl", path, ext} → {count, entries:[{path, name, dir, size}, …]}
host.exec Program execution with captured output, delegated to zwire_host::api::exec. {action:"host.exec", program, args:[…]} → {code, stdout, stderr}
zcite.save Writes a CSL-JSON reference (extracted from the active page by the extension's "Save to zcite") into zcite's inbox; zcite's inbox.import drains it into the library. {action:"zcite.save", item:<CSL-JSON object|array>} → {status:"ok", path, bytes}
dl.add Queues a segmented download: HEAD probe sizes the file, then N concurrent Range GETs into a pre-allocated destination. Falls back to a single stream when the server doesn't advertise Accept-Ranges. Cookies + User-Agent are forwarded so logged-in URLs work. {action:"dl.add", url, dir?, name?, segments?, cookies?, userAgent?, mask?} → {gid, dest}
dl.list Returns every job's current state, read from the file-state tracker rather than in-process memory — so the queue survives both a host exit and a service-worker restart. {action:"dl.list"} → {jobs:[…]}
dl.pause / dl.resume / dl.cancel / dl.restart Job control by gid. resume continues from the current byte offset; restart discards the partial file and re-downloads from byte zero. {action:"dl.pause", gid} (same shape for the other three)
dl.remove / dl.clear Drops one job, or every job in a scope, from the queue — optionally deleting the file from disk too. {action:"dl.remove", gid, deleteFromDisk} · {action:"dl.clear", scope, deleteFromDisk}
dl.openDir / dl.openFile Reveals the containing directory, or opens the finished file, with the platform opener. {action:"dl.openDir", dir} · {action:"dl.openFile", dir}
dl.writeFile / dl.writeFileChunk Chunked file sink the extension streams generated bytes into — the full-page screenshot ships its stitched PNG through it as base64 chunks, because native messaging caps a host→extension frame at 1 MiB. Colliding filenames auto-rename foo.zip → foo (1).zip. {action:"dl.writeFile", dir, name, base64} → {dest, bytes} · {action:"dl.writeFileChunk", sessionId, chunkIndex, base64, final} → {sessionId, chunkIndex, final, dest, bytes}

install

  1. cargo install zpwrchrome-host
  2. Register the binary for an extension ID: zpwrchrome-host --install <ext-id> — get the ext-id at chrome://extensions with Developer mode enabled.
  3. pass support requires GPG configured locally. The otp action shells out to pass otp, so it needs pass + pass-otp in $PATH.
  4. No terminal is needed to unlock: send pass.unlock with the passphrase, or use zpwrchrome's own unlock prompt.
  5. Used by zpwrchrome (a Chrome extension); also a drop-in for the upstream browserpass-extension with every additive action silently unused.

--install writes a manifest named com.menketechnologies.zpwrchrome.json into every Chromium-family config directory the user has, with allowed_origins restricted to the extension IDs passed on the command line. To use this binary as an upstream browserpass replacement instead, register it by hand under upstream's host name (<browser config dir>/NativeMessagingHosts/com.github.browserpass.native.json) — --install does not write that name.

port discipline reference

The src/ported/ tree is a 1:1 Rust mirror of the upstream Go source. Discipline borrowed from the zshrs PORT.md rules, adapted to a Go→Rust port:

Stem mirrorEvery file under src/ported/ mirrors a single upstream Go file by stem and relative subpath. errors/errors.go → src/ported/errors/errors.rs.
Doc-comment citationEvery Rust fn carries /// Port of <name>() from <go_file>:<line>.
Inline-comment citationEvery Go inline comment carries over to the Rust port with a // go:NN line-number citation on the corresponding Rust statement.
Identifiers verbatimGo's PascalCase / camelCase identifiers preserved (DetectGpgBinary, MakeConfigureResponse, parseRequestLength). File-level #![allow(non_snake_case)] documents the choice.
Local-name verbatimLocal variable names match Go's (gpgPath, normalizedStorePath, parentDir, responseData).
No invented helpersThe two recursive store walkers inside list.rs and tree.rs are inlined private fns at the call site — they replace external Go deps (mattn/go-zglob, mattn/go-zglob/fastwalk), not Go-source fns.

example request / response

Native-messaging frame: little-endian 4-byte length prefix + UTF-8 JSON. Same wire format as upstream. 

# list every entry in the "personal" store
# `stores` is an object keyed by store id, not an array
{"action":"list","settings":{"stores":{"personal":{"id":"personal","name":"Personal","path":"~/.password-store"}}}}

# → ok response: store-keyed file lists, paths keep their .gpg suffix
{"data":{"files":{"personal":["banking/example-bank.gpg","work/mail.gpg"]}},"status":"ok","version":3001002}

# fetch + decrypt one entry
{"action":"fetch","storeId":"personal","file":"work/mail.gpg","settings":{"stores":{...}}}

# → ok response: the plain text gpg --decrypt wrote to stdout
{"data":{"contents":"hunter2\nlogin: user\notpauth://totp/..."},"status":"ok","version":3001002}

# unlock the store so the --batch decrypt above can work without a terminal
{"action":"pass.unlock","storeId":"personal","passphrase":"…","settings":{"stores":{...}}}

# → ok response: names the probe entry it decrypted, never its contents
{"data":{"unlocked":true,"probe":"banking/example-bank.gpg"},"status":"ok","version":3001002}

# → error response: wrong passphrase (code 24 = UnableToDecryptPasswordFile)
{"code":24,"params":{"action":"pass.unlock","message":"Bad passphrase",...},"status":"error","version":3001002}
